# getBible Bookmarks API (v1)

This repository holds the static JSON files of the getBible topic bookmarks
API. Every file under `v1/` is generated by the `getbible/v1_bookmark_builder`
repository from its reviewed sources and committed here as-is. Nothing is
edited by hand, nothing runs here: a web server publishes the `v1/` directory
as plain files and consumers read them.

The catalogue is a set of **topics**. Each topic has a stable id, an English
name, a colour, optional alternative English wordings, a flag marking it as
part of the default starter set, translated names in many locales, and a list
of **verses** that speak to the topic. Verses are translation-independent
coordinates in the 66-book Protestant canon; no Scripture text is included.

## Files

| Path | Contents |
|---|---|
| `v1/index.json` | Discovery: schema version, catalogue version, checksum, counts, resource paths, locale list |
| `v1/all.json` | Everything: every topic with its verses and every locale with its names |
| `v1/catalog.json` | Every topic with its verses, without the locales |
| `v1/topics.json` | Topic list with verse counts, without the verse lists |
| `v1/topics/{id}.json` | One topic: metadata, its name in every locale, its verses |
| `v1/verses/{book}.json` | Reverse index for one book: chapter, verse, topic ids |
| `v1/verses/{book}/{chapter}.json` | Reverse index for one chapter: verse, topic ids |
| `v1/locales.json` | Locale list with language names and how many topics each translates |
| `v1/locales/{locale}.json` | Translated topic names for one locale (`en` is derived from the English names) |
| `v1/checksums.json` | SHA-256 of every other file in the tree |

Every canonical book (66) and chapter (1,189) has a file, even when no topic
links a verse in it; such a chapter file has an empty `verses` object. Every
topic and every locale listed in `index.json` has its own file.

## Documents

### `index.json`

```json
{
  "schema_version": 1,
  "catalog_version": 2,
  "checksum": "…64 hex characters…",
  "counts": { "topics": 61, "verses": 2155, "locales": 54 },
  "resources": { "topic": "topics/{id}.json", "chapter": "verses/{book}/{chapter}.json" },
  "locales": ["af", "ar", "…", "zh-hant"]
}
```

- `schema_version` changes only when the shape of these documents changes.
- `catalog_version` increases by one every time the content changes. Two
  builds with identical content keep the same number.
- `checksum` is the SHA-256 of the exact bytes of `all.json`. A consumer can
  verify a download or detect a change by hashing that one file.
- `resources` maps a resource name to its path template relative to `v1/`.

### Topic documents

A topic entry, as it appears in `all.json`, `catalog.json` and
`topics/{id}.json`:

```json
{
  "id": "gods-judgment",
  "name": "God's Judgment",
  "color": "#fb7185",
  "aliases": ["God's Judgement"],
  "default": true,
  "verses": [[45, 2, 5], [58, 9, 27]]
}
```

- `id` is a lowercase slug and is the stable key to store; names are display
  text and may be corrected.
- `color` is a six-digit lowercase hex colour meant for highlighting verses
  of that topic.
- `aliases` are other English wordings of the same topic, including previous
  names, so older references keep resolving.
- `default` marks the topics an application may present before the reader
  has made any choice of their own.
- `topics.json` carries the number of verses instead of the list;
  `topics/{id}.json` additionally carries `names`, the topic name in every
  locale that translates it, keyed by locale code.

### Verse coordinates

A verse is `[book, chapter, verse]`:

- `book` is 1 to 66 in Protestant canon order (table below).
- `chapter` is 1 up to the chapter count of that book.
- `verse` is the verse number within the chapter, as numbered in the common
  English versification. Translations that number verses differently should
  map by reference, not by position.

### Reverse index

`verses/{book}.json` groups the topics of a book by chapter and verse;
`verses/{book}/{chapter}.json` holds one chapter. Keys are chapter and verse
numbers as strings, values are sorted topic ids:

```json
{
  "schema_version": 1,
  "book": 43,
  "chapter": 3,
  "verses": {
    "3": ["spiritual-rebirth"],
    "5": ["baptism", "ordinances", "spiritual-rebirth"],
    "16": ["free-will", "spiritual-rebirth"],
    "36": ["what-is-life"]
  }
}
```

(An excerpt; the real John 3 file lists every linked verse of the chapter.)

### Locales

`locales.json` lists every locale with the number of topics it translates and
its English language name, which is `null` when none is recorded.
`locales/{locale}.json` maps topic ids to translated names for that locale
and carries `name` only when one is recorded:

```json
{
  "schema_version": 1,
  "locale": "fr",
  "name": "French",
  "topics": { "gods-judgment": "Jugement de Dieu", "grace": "Grâce" }
}
```

Locale codes are lowercase BCP 47 style tags such as `fr`, `zh-hans` or
`zh-hant`. `en` is always present and repeats the English names. A locale may
translate only part of the catalogue; the English name is the fallback.

### Checksums

`checksums.json` maps every path in the tree, except itself, to the SHA-256 of
that file's bytes, so any subset of files can be verified against the same
build.

## Changes

Files are regenerated as a whole from the sources. A topic that is removed
from the sources disappears from every document in the next build, together
with its verses and translations; its id may be used again later. Changes are
visible as ordinary commits in this repository's history.
